## 前言：BFC 到底在解决什么问题

写 CSS 的时候肯定遇到过这种诡异场景：

- 子盒子写 `margin-top: 30px`，结果父盒子被整体往下顶，子盒子纹丝不动
- 子元素一浮动，父容器高度直接没了，border 收成一条线
- 左侧 div 浮动，右侧普通 div 直接钻到左 div 底下被盖住

这三个问题看起来互不相干，但根因都是同一个——**普通文档流的布局规则在边界处失效了**。

BFC（Block Formatting Context，块级格式化上下文）就是浏览器给出的一套"隔离方案"：让某个元素内部成为一个独立的布局世界，里面的布局规则不影响外部，外部的 margin、float 也干扰不到内部。

所以 BFC 不是新东西，它是**用来填补普通文档流漏洞的补丁**。下面所有内容都围绕这一句话展开。

---

## 一、核心结论（直接背诵）

> **BFC 是浏览器的独立布局隔离区域。**

只要元素触发 BFC，就拥有 3 个核心能力，正好对应文档流下三大经典布局 bug：

1. **解决 margin 坍塌** —— 隔离内外边距，杜绝父子 margin 穿透、兄弟 margin 合并
2. **解决浮动高度塌陷** —— BFC 容器会识别内部浮动元素，自动撑开高度
3. **解决浮动覆盖问题** —— BFC 区域不会被浮动元素遮挡，可实现自适应两栏布局

一句话：**BFC 专治普通文档流下「margin 错乱、float 布局崩塌」**。

记住这三大能力，所有 BFC 题目都能反推出来。

---

## 二、触发 BFC 的所有条件

满足任意一条，元素就会生成 BFC 布局上下文。按记忆难度从易到难排：

| 编号 | 条件 | 备注 |
|------|------|------|
| 1 | 根元素 `<html>` | 页面天然就是 BFC |
| 2 | `float` 不为 `none` | 左浮动、右浮动都行 |
| 3 | `position: absolute / fixed` | 脱离文档流的定位 |
| 4 | `overflow` 不为 `visible` | `hidden` / `auto` / `scroll` |
| 5 | `display: inline-block` | 行内块 |
| 6 | `display: flow-root` | **现代最优、无副作用** |
| 7 | Flex 项目（flex 子项） | 容器本身是 FFC |
| 8 | Grid 项目 | 容器本身是 GFC |
| 9 | 表格系列元素 | `table` / `tr` / `td` / `thead` 等 |
| 10 | `column-count` | 多列布局 |
| 11 | `column-span: all` | 跨列元素 |

这一坨看起来很多，但实际开发里只有 4 号和 6 号常用，**6 号 `flow-root` 才是亲儿子**，下面会专门讲。

---

## 三、为什么 flex / grid 时代几乎碰不到 BFC

很多人会有这个疑惑：我天天写 flex / grid，好像一次都没显式用过 BFC？

原因在 W3C 规范里写得清清楚楚：

- `display: flex` 容器生成的是 **FFC（Flex Formatting Context）**，不是 BFC
- `display: grid` 容器生成的是 **GFC（Grid Formatting Context）**，也不是 BFC

但 flex / grid 的**子项**会触发 BFC（这就是上面表格的 7、8 条），并且 FFC / GFC 内部自带了一套新规则，直接把普通文档流那些毛病绕过去了：

- 子项禁止浮动 —— 不会出现浮动塌陷
- 自动消除 margin 合并 —— 不会出现 margin 坍塌
- 容器天然计算子项高度 —— 不会高度塌陷

**flex 直接规避了所有需要 BFC 解决的问题**，所以用 flex 写布局的人，几乎不需要关心 BFC。

BFC 只服务于**普通标准文档流**布局：那种 `div + float`、`div + margin`、`ul + li` 这种老派写法，才会撞上 BFC 的射程。

## 四、BFC 三大能力 + 完整代码示例

下面每个示例都是**问题 → 原因 → BFC 解决**三段式，方便对着代码看效果。

### 能力 1：解决 margin 坍塌（父子穿透 + 兄弟合并）

#### 问题 1：父子 margin 穿透（最常见）

子盒子想和父盒子产生间距，写了 `margin-top: 30px`，结果父盒子整体被往下顶，子盒子在父盒子里纹丝不动。

```html
<style>
  .father {
    background: #eee;
    width: 300px;
  }
  .child {
    width: 100px;
    height: 100px;
    background: orange;
    margin-top: 30px;
  }
</style>

<div class="father">
  <div class="child"></div>
</div>
```

**原因**：普通文档流里，父子块级元素的垂直 margin 会发生**穿透合并**。子元素的 `margin-top` 直接"漏"到了父元素身上，看上去就像子元素没动、父元素被顶下来。

**BFC 解决**：在子元素外层套一层 BFC 容器，把这股 margin 力量隔离在 BFC 内部。

```html
<style>
  .wrap {
    display: flow-root; /* 开启纯净 BFC */
  }
</style>

<div class="father">
  <div class="wrap">
    <div class="child"></div>
  </div>
</div>
```

`.wrap` 变成 BFC 后，内部 child 的 `margin-top` 不会穿透到 `.wrap` 外部，自然就规规矩矩地撑开了和 father 的间距。

#### 问题 2：兄弟垂直 margin 合并

上下两个块级元素，上盒子的 `margin-bottom` 和下盒子的 `margin-top` **不会叠加**，只会取较大值。

```html
<style>
  .a { margin-bottom: 30px; }
  .b { margin-top: 20px; }
</style>

<div class="a">A</div>
<div class="b">B</div>
<!-- 实际间距：30px，不是 50px -->
```

**BFC 解决**：把其中一个盒子单独放进 BFC 容器，阻断合并通道。

```html
<div class="a">A</div>
<div class="bfc-wrap" style="display: flow-root;">
  <div class="b">B</div>
</div>
<!-- 实际间距：50px -->
```

这种场景实际项目里很少特意去解，更多是通过 flex / grid 直接绕过。

---

### 能力 2：解决浮动导致父元素高度塌陷

子元素一浮动，就脱离了文档流，父盒子抓不到子元素的高度，`border` 收成一条红线。

```html
<style>
  .parent {
    border: 2px solid red;
  }
  .son {
    width: 100px;
    height: 100px;
    background: blue;
    float: left;
  }
</style>

<div class="parent">
  <div class="son"></div>
</div>
```

父容器 `.parent` 高度变成了 0，只看到顶部一条红色 border，蓝色 son 浮在外面。

**BFC 修复**：父容器开启 BFC，BFC 内部规则规定**必须计算浮动子元素的高度**。

```css
.parent {
  display: flow-root;
}
```

一行 `flow-root`，父容器自动撑开到 100px。

> 老写法是 `overflow: hidden`，也能触发 BFC 起作用，但会裁剪溢出内容，下面专门讲副作用。

---

### 能力 3：解决浮动覆盖普通元素（实现两栏自适应）

BFC 有一条铁律：**BFC 区域不会与浮动元素重叠**。

利用这条规则，可以天然实现"左侧固定宽度浮动 + 右侧自适应"的经典两栏布局，不用写什么 `calc`、`flex`。

```html
<style>
  .left {
    width: 150px;
    height: 200px;
    background: #409eff;
    float: left;
  }
  .right {
    height: 200px;
    background: #67c23a;
    display: flow-root; /* BFC 避开浮动 */
  }
</style>

<div class="left">左侧固定栏</div>
<div class="right">右侧自适应内容区</div>
```

不加 `flow-root` 的话，`.right` 会整个钻到 `.left` 底下（因为 `.left` 浮动脱离文档流，`.right` 会顶上来占满一整行）。加上之后，`.right` 变 BFC，自动给 `.left` 让位，右侧填满剩余宽度。

## 五、传统 BFC 属性的副作用 & 为何推荐 flow-root

下面这些属性虽然都能触发 BFC，但都带着各自的"原罪"，**开发中不推荐**：

| 属性 | 副作用 |
|------|--------|
| `overflow: hidden` | 溢出内容会被裁剪，下拉菜单、阴影、tooltip 全废 |
| `overflow: auto` | 内容溢出会冒出滚动条 |
| `display: inline-block` | 产生空白间隙（行内元素默认间距）、不再独占一行 |
| `float: left / right` | 脱离文档流，破坏整体布局，把自己又变成新的问题 |
| `position: absolute / fixed` | 完全脱离文档流，父容器又塌陷了 |

所以最优解只有一个：

```css
.box {
  display: flow-root;
}
```

`flow-root` 这个值是 CSS 为 BFC 专门设计的"纯净触发器"：

- 只开启 BFC 隔离能力
- 不裁剪内容（不像 overflow:hidden）
- 不出滚动条
- 不破坏自身布局（不脱离文档流、不变成行内块）
- 语义化：从名字就能看出意图——让这个元素成为流布局的根

**现代项目里看到 BFC 就该条件反射写 `flow-root`，其他都是历史包袱。**

## 六、最终总结（面试背诵版）

### 1. BFC 是什么

浏览器里的独立布局隔离区域。内部布局不影响外部，外部也不干扰内部。

### 2. BFC 能干什么（核心三功能）

- 解决父子、兄弟 margin 坍塌合并
- 解决浮动子元素导致父容器高度塌陷
- 解决浮动覆盖问题，实现自适应两栏布局

### 3. 触发 BFC 的常见条件

根元素、float 不为 none、absolute / fixed、overflow 不为 visible、inline-block、**flow-root**、flex / grid 子项、表格元素、多列布局。

### 4. 现代开发为什么很少用 BFC

flex / grid 是全新 FFC / GFC 上下文，自带规则直接绕开了普通文档流的 margin 合并、浮动塌陷等问题。BFC 只服务于传统的 float + div 布局。

### 5. 最佳实践

需要 BFC 隔离时，统一使用 `display: flow-root`，无任何副作用。

---

## 七、一句话收尾

BFC 不是新东西，是浏览器给普通文档流打的补丁。flex / grid 时代，BFC 的舞台越来越小，但只要项目里还有 `float` 或者老派布局，BFC 这套东西就得记牢——尤其是 `flow-root`，一个属性顶过去一堆副作用写法。
