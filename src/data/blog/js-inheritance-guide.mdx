## 前言：继承是怎么产生的

提到继承，就得先讲面向对象编程（OOP）。面向对象最早出现在 Java 和 C++ 中，核心思路是把现实世界的事物抽象成**类**，类的内部封装自己的属性和行为。在用类的过程中会遇到一个问题：多个类存在大量重复代码，自己独有的代码只占少量。

为了解决这个问题，就产生了**继承机制**——把多个类里面共有的逻辑提取出来作为一个**父类 / 基类**，子类直接复用父类的属性和行为，自己只需要关注独有的代码即可。

### JS 的特殊之处

JS 的诞生受到了 Java 的启发，但它并没有传统意义上的类。JS 属于**原型式面向对象**，没有 class（ES6 之前），一切基于**原型（prototype）**。

在原型机制上，JS 用以下手段模拟继承：

- `prototype` 原型链
- `call / apply` 改变 this 指向
- `Object.create` 创建关联对象

> 注意：本文后面六种继承方式全部使用**同一个父类 `Animal`**，并且前一种方式的测试输出会影响后面读者对后一种方式的理解——前一种的缺点就是下一种的出发点，是层层递进、依次相存的关系。

## 1. 前置：为什么要用 new 调用函数

在讲继承之前，必须先搞懂一个核心问题：**为什么构造函数一定要用 `new` 来调用？**

先构造父类 / 基类 `Animal`（后面所有继承方式都共用这个）：

```js
function Animal(name) {
  this.arr = ['张三', '李四', '王五']

  // this 指向什么？取决于怎么调用
  console.log('查看 this 的指向', this)

  // 在 Animal 实例上挂载 name 属性
  this.name = name || '动物'

  // 在 Animal 实例上挂载 sleep 实例方法
  this.sleep = function () {
    console.log(this.name + '正在睡觉')
  }
}

// 在 Animal 原型上挂载 nickName 属性
Animal.prototype.nickName = '动物'

// Animal 是函数，函数都有 prototype 属性（原型）
// 这个属性会初始化一个空对象，空对象里有个 constructor 属性指向函数本身
// 给 Animal 原型属性上添加 eat 方法
Animal.prototype.eat = function (food) {
  console.log(this.name + '正在吃' + food)
}
```

### 不 new 会怎么样

**直接调用** `Animal()` 不走 `new` 操作符，此时 `this` 指向全局对象：
- 浏览器中指向 `window`
- Node 中指向 `global`
- 严格模式下指向 `undefined`

这样就成了给全局对象添加属性和行为，造成**全局污染**。严格模式下连 this 都没有，根本实现不了继承。

**用 `new` 调用** `new Animal(xxx)` 时，`new` 操作符会创建一个空对象，并把 `this` 指向这个新对象。函数执行完毕后，自动把这个对象返回。此时 `this` 上就有了 `name` 属性和 `sleep` 实例方法。

> 一句话：**要实现继承，必须用 `new` 操作符调用构造函数**。不 new 的话 this 乱飞，属性挂到全局对象上，实现不了继承。

## 2. 第一种：原型链继承

### 原理

核心写法：**子类的原型对象 = 父类的实例对象**。这样子类原型里就装着父类的属性和方法，子类自己找不到时，顺着原型链一路向上找——正好命中父类实例上的东西。

```js
// 创建子类 Dog，它有自己独有的属性 like
function Dog() {
  this.like = '吃骨头'
}

// 👇 修改子类原型指向，让子类原型对象 = 父类实例对象
Dog.prototype = new Animal()

// 在 Dog 原型上再加一个 name 属性（会覆盖父类实例上的默认值）
Dog.prototype.name = '狗'
```

### 测试

```js
const dog = new Dog()   // 实例 1
const dog1 = new Dog()  // 实例 2

console.log(dog.name)                     // 狗
console.log(dog.eat('骨头'))               // 狗正在吃骨头
console.log(dog.sleep())                  // 狗正在睡觉
console.log(dog instanceof Animal)        // true
console.log(dog instanceof Dog)           // true
console.log('dog1 拿到原型上的昵称：', dog1.nickName)  // 动物
```

### 致命缺陷：引用类型属性被所有实例共享

```js
dog1.arr.push('赵六')
console.log(dog.arr)   // ['张三', '李四', '王五', '赵六']
console.log(dog1.arr)  // ['张三', '李四', '王五', '赵六']  ← 两个实例共享同一个 arr！
```

原因：所有 Dog 实例共享同一个父类实例作为原型（`new Animal()` 只执行了一次，那里面的 `arr` 就只有一份）。**一个实例改了引用类型，所有实例读出来的都变了**。

### 总结

| 优点 | 缺点 |
|------|------|
| 实现简单，子类能继承父类实例属性 + 原型属性 | **引用类型属性被共享**，一个改全部变 |
| | 创建子类实例时，无法向父类构造函数传参 |

原型链继承的「引用共享」问题，必须解决。

---

## 3. 第二种：构造函数继承（借用构造函数）

### 原理

为了解决原型链继承的引用共享问题，引入构造函数继承。核心思路：**在子类构造函数里调用父类构造函数，用 `call` 把父类的 this 换成子类实例**。每次创建子类实例，都会重新执行一遍父类构造函数，每个实例都能拿到自己独立的一份属性。

```js
function Cat(name) {
  // 调用父类方法，改变 this 指向
  // 此时 this 指向 Cat 的实例对象
  // 相当于把父类函数内部的属性和方法全部复制一遍给子类实例
  Animal.call(this)
  this.name = name || 'Tom'
}
```

`Animal.call(this)` 执行时，Animal 里的 `this.arr = [...]`、`this.sleep = ...` 全挂到 `new Cat()` 创建出来的实例上。每个实例都有自己独立的 `arr`，互不干扰。

### 测试

```js
const cat1 = new Cat()
const cat2 = new Cat()

cat1.arr.push('田七')
console.log(cat1.arr)           // ['张三', '李四', '王五', '田七']
console.log(cat2.arr)           // ['张三', '李四', '王五']  ← cat2 没被影响，独立了！

console.log(cat1 instanceof Animal)   // false  ← 原型链断了
console.log(cat2 instanceof Cat)      // true
console.log('cat1 拿原型上的昵称：', cat1.nickName)  // undefined  ← 拿不到原型上的东西
```

### 总结

| 优点 | 缺点 |
|------|------|
| 解决了引用类型属性共享的问题，每个实例独立 | **子类无法继承父类原型上的属性和方法**（原型链断了） |
| 创建子类实例时可以向父类传参 | `instanceof` 检测不出子类和父类的关系 |

原型共享问题解决了，但原型上的东西拿不到了。换个思路——**能不能在子类里 new 一个父类实例，给它加属性然后直接 return？** 这就是实例继承。

---

## 4. 第三种：实例继承

### 原理

实例继承的思路和前两种都不一样：**在子类构造函数内部，手动 new 一个父类实例，给这个实例加自己的属性和方法，然后把它 return 出去**。虽然子类外面还是写 `new 子类()`，但拿到手的其实是父类实例。

```js
function Rabbit(name) {
  // 在子类内部 new 一个父类实例
  const instance = new Animal()

  // 给父类实例加自己的属性和方法
  instance.name = name || '兔子'
  instance.like = '胡萝卜'

  // 直接 return 这个增强后的父类实例
  return instance
}
```

> 关键点：构造函数里如果 `return` 了一个对象，`new Rabbit()` 的结果就是这个 return 的对象，而不是 `new` 默认创建的 this。

### 测试

```js
const rabbit1 = new Rabbit()
const rabbit2 = new Rabbit('小白兔')

console.log(rabbit1.name)                    // 兔子
console.log(rabbit1.eat('胡萝卜'))            // 兔子正在吃胡萝卜  ✅ 能调父类原型方法
console.log(rabbit1.nickName)                // 动物  ✅ 能拿父类原型属性
console.log(rabbit1.like)                    // 胡萝卜

rabbit1.arr.push('赵六')
console.log(rabbit1.arr)  // ['张三', '李四', '王五', '赵六']
console.log(rabbit2.arr)  // ['张三', '李四', '王五']  ← 独立，没共享

console.log(rabbit1 instanceof Animal)   // true
console.log(rabbit1 instanceof Rabbit)   // false  ← 坑！原型链指向的是 Animal，不是 Rabbit
```

### 总结

| 优点 | 缺点 |
|------|------|
| 可以向父类传参 | **子类实例 instanceof 子类为 false**（因为 return 的是父类实例） |
| 每个实例有独立的一份 | 子类自己原型上挂不了东西（返回的不是子类 this） |
| 能拿到父类原型上的属性和方法 | — |

实例继承巧妙绕过了 call(this) 带来的原型链断裂，但因为 return 的是父类实例，**子类自己被架空了**——子类原型、子类 constructor 全都没意义，分不清它到底是 Rabbit 还是 Animal。

换个思路：**不操作 this、不 new 父类实例，直接把父类的属性和方法一个一个「拷」到子类上**，这就是拷贝继承。

---

## 5. 第四种：拷贝继承

### 原理

拷贝继承分两步：
1. **实例属性拷贝**：子类构造函数里先 new 一个父类实例，然后 `for...in` 把它上面所有属性逐个拷到子类实例上
2. **原型属性拷贝**：再 `for...in` 把父类原型上的属性和方法，逐个拷到子类原型上

全程不搞原型链、不搞 call，就是「一个一个复制粘贴」。

```js
function Sheep(name) {
  // 1. 先搞一个父类实例作拷贝源
  const animal = new Animal()

  // 2. 实例属性拷贝：for...in 遍历父类实例，挨个挂到 this（子类实例）上
  for (const p in animal) {
    this[p] = animal[p]
  }

  this.name = name || '绵羊'
}

// 3. 原型属性拷贝：for...in 遍历父类原型，挨个挂到子类原型上
for (const p in Animal.prototype) {
  Sheep.prototype[p] = Animal.prototype[p]
}

// 自己再加一个子类原型方法
Sheep.prototype.baa = function () {
  console.log('咩咩')
}
```

### 测试

```js
const sheep1 = new Sheep()
const sheep2 = new Sheep('喜羊羊')

console.log(sheep1.name)            // 绵羊
console.log(sheep1.eat('草'))        // 绵羊正在吃草
console.log(sheep1.nickName)        // 动物
sheep1.baa()                        // 咩咩

sheep1.arr.push('田七')
console.log(sheep1.arr)  // ['张三', '李四', '王五', '田七']
console.log(sheep2.arr)  // ['张三', '李四', '王五', '田七']  ← 又共享了！
```

为什么 sheep2.arr 也变了？——因为 `this[p] = animal[p]` 把数组引用赋过去了，两个实例引用同一份数组。**引用类型还是共享。**

```js
console.log(sheep1 instanceof Animal)  // false  ← 原型链没连
console.log(sheep1 instanceof Sheep)   // true
```

### 总结

| 优点 | 缺点 |
|------|------|
| 既能拿父类实例属性，又能拿父类原型属性 | **引用类型属性依然共享**（拷贝的是引用） |
| 支持多继承（拷贝多个父类） | `for...in` 枚举拷贝效率低 |
| | `instanceof` 检测不出子类和父类关系 |
| | 不可枚举的属性、原型链上非自身的属性拷贝不到 |

现在我们手里四种方式：

| 方式 | 引用独立 | 继承父类原型 | instanceof 父子关系 | 其他问题 |
|------|---------|------------|-------------------|---------|
| 原型链继承 | ❌ 共享 | ✅ 能 | ✅ 是 | — |
| 构造函数继承 | ✅ 独立 | ❌ 不能 | ❌ 不是 | — |
| 实例继承 | ✅ 独立 | ✅ 能 | ❌ 不是子类 | 子类被架空 |
| 拷贝继承 | ❌ 共享 | ✅ 能（拷贝过来） | ❌ 不是 | 效率低 |

就没有一种「引用独立 + 原型能继承 + instanceof 也对」的吗？——有，**组合继承**，就是把「构造函数继承」和「原型链继承」拼起来。

## 6. 第五种：组合继承（原型链 + 构造函数结合）

### 原理

组合继承是「构造函数继承」和「原型链继承」两种方式的结合，取长补短：

```js
function Chicken(name) {
  // 1. 构造函数继承：把父类实例属性复制一份到子类实例身上（解决引用共享）
  Animal.call(this)
  this.name = name || 'Tom'
}

// 2. 原型链继承：让子类原型指向父类实例（继承父类原型上的属性和方法）
Chicken.prototype = new Animal()
```

### 测试

```js
const chicken1 = new Chicken()
const chicken2 = new Chicken()

chicken1.arr.push('田七')
console.log(chicken1.arr)  // ['张三', '李四', '王五', '田七']
console.log(chicken2.arr)  // ['张三', '李四', '王五']  ← 实例属性独立了

console.log(chicken1 instanceof Animal)   // true
console.log(chicken2 instanceof Chicken)  // true
console.log('chicken1 拿原型上的昵称：', chicken1.nickName)  // 动物  ← 原型上也拿到了
```

引用类型独立了，原型上的属性也能继承了，instanceof 也对了，看似完美。

### 缺点：父类构造函数被调用了两次

仔细看这段代码，`Animal` 被调用了**两次**：

1. `Animal.call(this)` —— 在子类构造函数内部调一次，把实例属性（`arr`、`name`、`sleep`）复制给子类实例
2. `new Animal()` —— 设置子类原型时调一次，父类实例属性被挂到子类原型上

第二次调用完全多余，因为子类实例已经通过 `call` 拥有了父类的实例属性，原型上再放一份纯属冗余。每次创建子类类型（写 `Chicken.prototype = new Animal()` 这一行时）就把父类构造函数整个跑一遍，浪费性能。

### 总结

| 优点 | 缺点 |
|------|------|
| 解决了引用类型共享问题 | **父类构造函数被调用了两次**，性能浪费 |
| 子类能继承父类原型上的属性和方法 | 子类原型上冗余了一份父类实例属性 |
| instanceof 正常工作 | — |

现在要做的事很明确：**把组合继承里第二次 `new Animal()` 调父类构造函数这一步，换成一个不调构造函数、但能建立原型关联的操作**。这个操作就是 `Object.create`，最终方案——**寄生组合继承**。

## 7. 第六种：寄生组合继承（最终最优方案）

### 为什么名字里有「寄生」和「组合」

先把名字掰明白：

- **组合** = 用 `Animal.call(this)` 做构造函数继承（继承实例属性，和组合继承的第一步一样）
- **寄生** = 用 `Object.create(Animal.prototype)` 创建一个空对象，这个空对象的原型直接指向父类原型，**不调父类构造函数**。为什么叫「寄生」？因为这个思路脱胎于 Crockford 的「原型式继承 / 寄生式继承」思想——创建一个过渡的空对象当「寄生体」，只建立原型关联，不执行构造逻辑。ES5 把这个思想标准化成了 `Object.create`。

所以：**寄生组合继承 = 构造函数继承（拿实例属性） + Object.create 建立原型关联（拿原型方法，不调第二次构造函数）。**

### 完整实现

```js
function Pig(name) {
  // 1. 构造函数继承：复制父类实例属性
  Animal.call(this)
  this.name = name || 'Tom'
}

// 2. 👇 核心：Object.create 创建一个空对象，空对象的原型 = Animal.prototype
//    子类原型指向这个空对象 → 子类原型最终关联到父类原型
//    不执行 Animal 构造函数！没有第二次调用了
Pig.prototype = Object.create(Animal.prototype)

// 3. 修正 constructor 指向
//    Object.create 之后 Pig.prototype.constructor 指向的是 Animal
//    明明是 new Pig() 创建出来的实例，constructor 却指向父类，信息错乱
Pig.prototype.constructor = Pig
```

对比一下组合继承，把 `Chicken.prototype = new Animal()` 换成 `Pig.prototype = Object.create(Animal.prototype)`，父类构造函数就只在 `Animal.call(this)` 调一次。

### Object.create vs new 对比

| 写法 | 是否调用 Animal 构造函数 | 子类原型上的内容 |
|------|------------------------|-----------------|
| `Child.prototype = new Animal()` | ✅ 调用（多余开销） | 父类实例属性（冗余） + 父类原型上的属性方法 |
| `Child.prototype = Object.create(Animal.prototype)` | ❌ 不调用 | 只有父类原型上的属性方法，干净 |

### 测试

```js
const pig1 = new Pig()
const pig2 = new Pig()

pig1.arr.push('田七')
console.log(pig1.arr)  // ['张三', '李四', '王五', '田七']
console.log(pig2.arr)  // ['张三', '李四', '王五']  ← 实例属性独立

console.log(pig1 instanceof Animal)  // true
console.log(pig2 instanceof Pig)     // true
console.log('pig1 拿原型上的昵称：', pig1.nickName)  // 动物  ← 原型也能继承
```

### 一个容易踩的坑：子类原型方法添加顺序

```js
function Pig(name) {
  Animal.call(this)
  this.name = name || 'Tom'
}

// ❌ 在覆盖原型之前先挂子类方法
Pig.prototype.PigFun = function () {
  console.log('我是猪的实例方法')
}

// 这一步把 Pig.prototype 整个替换成新对象，之前挂在旧 prototype 上的 PigFun 就丢了！
Pig.prototype = Object.create(Animal.prototype)
Pig.prototype.constructor = Pig

const pig = new Pig()
pig.PigFun()  // TypeError: pig.PigFun is not a function
```

✅ **正确写法：先覆盖原型，再添加子类自己的方法**：

```js
function Pig(name) {
  Animal.call(this)
  this.name = name || 'Tom'
}

// 1. 先替换原型，修正 constructor
Pig.prototype = Object.create(Animal.prototype)
Pig.prototype.constructor = Pig

// 2. 再添加子类的实例方法
Pig.prototype.PigFun = function () {
  console.log('我是猪的实例方法')
}

const pig = new Pig()
pig.PigFun()  // 我是猪的实例方法 ✅
```

### 总结

| 优点 | 缺点 |
|------|------|
| **只调用一次父类构造函数**，没有冗余 | 写法相对复杂 |
| 实例属性独立，不共享引用 | — |
| 子类能继承父类原型上的属性和方法 | — |
| `instanceof` 正常工作 | — |

**寄生组合继承是 ES6 之前最完善、最优的继承方案。**

## 8. ES6 class extends：语法糖的真相

ES6 引入了 `class` 和 `extends`，写法一下变得非常直观、干净：

```js
class Animal {
  constructor(name) {
    this.arr = ['张三', '李四', '王五']
    this.name = name || '动物'
  }

  sleep() {
    console.log(this.name + '正在睡觉')
  }

  eat(food) {
    console.log(this.name + '正在吃' + food)
  }

  // 静态方法，挂在构造函数本身上
  static create(name) {
    return new Animal(name)
  }
}

class Dog extends Animal {
  constructor(name) {
    super(name)  // 等价于 Animal.call(this, name)
    this.like = '吃骨头'
  }

  bark() {
    console.log('汪汪')
  }
}

const dog = new Dog('狗')
dog.sleep()      // 狗正在睡觉
dog.eat('骨头')   // 狗正在吃骨头
dog.bark()       // 汪汪
console.log(dog instanceof Animal)  // true
```

### class 的本质：寄生组合继承的语法糖

`class extends` 看着像 Java，但底层还是那套。babel 把 `class extends` 编译成 ES5，核心就是寄生组合继承：

| ES6 写法 | ES5 等价操作 |
|----------|-------------|
| `constructor` | 构造函数本身 |
| `super(name)` | `Animal.call(this, name)`（构造函数继承那一步） |
| `extends Animal` | `Child.prototype = Object.create(Animal.prototype)` + 修正 constructor（原型关联那一步） |
| 类上的方法（非 static） | 挂在 `Child.prototype` 上 |
| `static` 方法 | 挂在构造函数本身（Child）上 |

> 所以说：**ES6 class 只是语法糖，底层实现就是寄生组合继承**。

## 9. 六种继承方式对比总览

| 继承方式 | 核心写法 | 引用类型独立？ | 继承父类原型？ | instanceof 是父类？ | 其他问题 |
|----------|---------|--------------|--------------|-------------------|---------|
| **① 原型链继承** | `Child.prototype = new Parent()` | ❌ 共享 | ✅ 能 | ✅ 是 | — |
| **② 构造函数继承** | `Parent.call(this)` | ✅ 独立 | ❌ 不能 | ❌ 不是 | — |
| **③ 实例继承** | 子类内部 `new Parent()` 后 return 它 | ✅ 独立 | ✅ 能 | ✅ 是父类，但 ❌**不是子类** | 子类被架空 |
| **④ 拷贝继承** | `for...in` 挨个拷实例和原型属性 | ❌ 共享 | ✅ 拷贝了一份 | ❌ 不是 | 效率低；不可枚举拷不到 |
| **⑤ 组合继承** | `call(this)` + `prototype = new Parent()` | ✅ 独立 | ✅ 能 | ✅ 是 | 父类构造函数调了两次 |
| **⑥ 寄生组合继承** | `call(this)` + `Object.create(Parent.prototype)` | ✅ 独立 | ✅ 能 | ✅ 是 | 写法稍复杂 |
| **ES6 class extends** | `class Child extends Parent { super() }` | ✅ 独立 | ✅ 能 | ✅ 是 | 语法糖，底层同⑥ |

### 完整演进链条

```
 ① 原型链继承
      │
      │ 致命缺陷：引用类型共享 → 一个改全变
      ▼
 ② 构造函数继承 Parent.call(this)
      │  解决了引用共享
      │  新问题：原型链断裂 → 拿不到父类原型上的方法
      ▼
 ┌──────────────────────────────────────┐
 │ 两条并行探索：不同思路拿父类原型方法     │
 │                                      │
 │ ③ 实例继承：子类里 new 父类再 return    │
 │    能拿到父类原型，但子类自己被架空      │
 │                                      │
 │ ④ 拷贝继承：for...in 挨个拷            │
 │    能拷父类原型，但引用共享 + 效率低     │
 └───────────────┬──────────────────────┘
                 │  两种都不理想
                 ▼
 ⑤ 组合继承（call + prototype = new Parent）
      │  引用独立 + 原型继承都搞定
      │  新问题：父类构造函数调了两次
      ▼
 ⑥ 寄生组合继承（call + Object.create）
      │  取「构造函数继承」的实例属性独立
      │  取「Object.create」不调构造函数建原型
      │  ✅ 完美方案，只调一次
      ▼
 ES6 class extends（语法糖包装）
```

每一种方式都是为了解决前一种方式的遗留缺陷而诞生，层层推进，最终寄生组合继承成为 ES5 时代的最优解，ES6 class 只是把它包装成了更优雅的语法。
